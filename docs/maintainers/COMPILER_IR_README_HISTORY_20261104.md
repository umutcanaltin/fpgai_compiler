## Working paper

**FPGAI: An Architecture-Semantic Intermediate Representation for FPGA Neural-Network Compilation**

A new FPGA neural-network research compiler is the paper's subject. The central scientific claim to **test** is that explicit operator-local space–time mappings, together with typed architectural interfaces between operators and refinement-preserving HLS lowering, enable whole-graph architecture choices to be represented, checked, and materialized as a coherent compiler representation instead of disconnected backend knobs.

This is **not** a claim that multilevel IR, scheduling, PE/SIMD, neural-network accelerator customization, graph dataflow, HLS correctness, or reinforcement learning were invented here. Related work: FINN/FINN-R, hls4ml, fpgaConvNet, Timeloop, MAESTRO, AutoSA, Halide, TVM, HeteroCL, Spatial, MLIR, ScaleHLS, HIDA, Calyx/CIRCT and HLS verification. Write comparisons using demonstrated abilities, not unverifiable absence claims.

## Research questions and proposed contributions

| ID | Research question | Candidate contribution | Minimum evidence |
| --- | --- | --- | --- |
| C1 / RQ1 | Can a typed neural-network graph retain mathematical identity while different operators have independently resolvable spatial, temporal, numerical and execution choices? | **Architecture-semantic Model IR** with Functional → Architectural → Lowered refinement, explicit per-operator mapping `Phi`, scopes, requested/effective contracts and typed physical interface obligations. | Executable operator-level and multi-operator IR examples; independent legality/trace checking; distinct effective configurations with same functional graph. |
| C2 / RQ2 | Can separately legal operator mappings be composed into a legal whole-network implementation without silently assuming matching hardware interfaces? | **Compositional architecture interfaces and legalization**, including type/shape/precision, buffer/transfer/layout protocol and schedule compatibility *only where materialized by this research backend*. | Cases that are individually legal but jointly incompatible; explicit rejection or demonstrably implemented conversion/transfer; independent numeric and structural tests. |
| C3 / RQ3 | Can an effective space–time mapping be traced into real generated HLS, rather than represented as a detached optimization configuration? | **Architecture-preserving lowering** with per-decision provenance, explicit obligations, source-loop/host-executed `Phi` checks and HLS evidence tiers. | CPU checker + actual generated C++ trace + matched original Vitis CSim/CSynth; detailed checked vs unsupported semantics. |
| C4 / RQ4 | Does the representation expose useful independent whole-graph architecture choices without altering the mathematical model? | **Measured design-space expressiveness**, meaningful distinct vs equivalent effective mappings, acceptance rates, verification time, small source-attested HLS trade-offs. | Reproducible enumeration, equivalence classes, matched restricted-IR ablation, and limited HLS resource/latency measurements. |

**Main research bet:** C1+C2 (operator architecture semantics **plus graph-level composition**) is the headline. C3 shows FPGAI is a real compiler; C4 provides quantitative practical evidence. Architecture-intent conformance, mutation tests, and equivalence analysis are **validation methods**, not automatically independent primary contributions.

## Representation and scope

```text
ONNX / typed graph
  → Functional Model IR      operators, tensors, dimensions, numerical semantics, graph edges
  → Architectural Model IR   per-operator Phi: precision, tiling, replicas, PEs,
                             SIMD lanes, temporal reuse, pipeline; scopes;
                             typed architecture boundary/interface contracts
  → Lowered Model IR         resolved compute structures and, only when valid,
                             explicit interface adapters/conversions/transfer
  → generated HLS C++        staged original Vitis CSim → CSynth evidence
```

`Phi_v(i) = (q, kappa, r, p, ell, f, g)` is the *existing* operator space–time formulation. The key **prospective extension** is typed architectural interface/composition semantics across edges and safe lowering of them. Numerical format, SIMD width and PE number alone do **not** imply a buffer, cast or wire conversion: derive requirements from the selected producer/consumer execution contract; reject unsupported adapters instead of inventing them.

The research backend is **not** the full Morfics heterogeneous five-layer VHDL-first product. Keep the research's Functional/Architectural/Lowered Model IR separate from the product's System/Model/Math/Circuit/Physical architecture and never imply multi-vendor qualification here.

## Falsifiable hypotheses

- **H1:** For a defined supported operator subset, C1+C2 represents legal operator-local architectures and rejects unsupported cross-operator compositions that a restricted per-operator-only configuration interface does not distinguish.
- **H2:** C3 preserves specified spatial/temporal contract obligations through actual generated source in tested configurations; any unsupported or unverified physical property remains explicitly unverified.
- **H3:** C1+C2 yields a strictly larger set of *verified distinct whole-graph architectural representations* than the deliberately restricted single-architecture/fixed-interface ablation, with no reduction in numerical correctness.
- **H4 (exploratory):** A small independently sourced native HLS sample demonstrates meaningful architecture diversity and exposes feasibility/latency/resource trade-offs; faster-than-hls4ml is NOT assumed.

Report failures, zero-distinctness, and mismatched/unqualified HLS cases honestly. Do not equate equal IR fingerprints with equal routed designs.

## Future machine-learning / RL suitability — permitted claim

The architecture-semantic IR **is designed to be machine-learning- and reinforcement-learning-compatible** because a typed variable-size operator graph plus legal, scoped architectural decisions and constraints can be exposed as observations and masked actions, while the compiler independently checks and lowers the proposals. This is an **interface/design claim**, not evidence that RL search is efficient, converges, generalizes, or outperforms other search strategies.

Minimal no-training demonstration for this paper:
1. Export a deterministic typed graph observation (operator kinds, shapes, edges, resource/error constraints, current/effective architecture; applicability masks).
2. Export a compiler-derived, legal finite candidate menu and/or typed decision schema; reject invalid requests before native tools.
3. Round-trip one *scripted or seeded non-learning* proposal through Architectural IR → Lowered IR → generated HLS (CPU-only by default), preserving source IDs and mapping fingerprints.
4. Show changing operator counts/shapes does not require a new *observation schema*. Do not claim all operator families are already supported.
5. The Gym learning experiments, if later resumed, are separately source-pinned research; **no RL results are evidence of the new IR's novelty** and no RL training is needed for first-paper acceptance.

Suggested honest abstract phrase: “The resulting representation exposes a typed, graph-structured interface to future automated design-space search, including reinforcement-learning agents; evaluation of learning performance is outside this paper.”

**Never write:** “FPGAI IR is optimized for RL”, “improves RL training efficiency”, “generalizes across networks”, or “is the first RL-ready compiler IR” without independent matched evidence.

## Stronger IR novelty checkpoint (1 November 2026)

**Read [Compositional Space–Time Model IR novelty specification](COMPOSITIONAL_SPACETIME_IR_NOVELTY.md) before implementing IR-02/03.** Recent closely relevant work includes **Allo (PLDI 2024)** for compositional compute/memory/communication/data type customization, **HIDA (ASPLOS 2024)** for hierarchical functional/structural dataflow, **StreamTensor (MICRO 2025)** for typed streaming tensor layouts/communication, and **Stream-HLS (2025)** for multi-kernel scheduling. Thus typed graph edges, customized kernels, static schedules, adapter insertion, or a three-stage IR do not independently establish novelty. The prospective differentiating object is a *compositional relation between each operator's logical iteration-to-space/time map and each tensor element's production, availability, storage/layout and downstream consumption*, with a real HLS-lowered alternative and independently tested obligations. Treat this as a **hypothesis**, not a proven first-of-kind claim. The initial source-array inspector and existing per-op Phi are merely starting points.
