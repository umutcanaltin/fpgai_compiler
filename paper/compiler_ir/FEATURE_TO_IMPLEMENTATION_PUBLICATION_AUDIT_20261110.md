## Required release decision checks

1. **Local source correctness:** On exact new SHA run `python -m pytest -q tests/test_cst_graph_phi_independent_issue.py tests/test_cst_graph_phi_source.py tests/test_cst_graph_edge_witness.py`, then full `python -m pytest -q`; run `make research-audit-tests`. Save actual pass/skip/fail counts without relabeling old observations.
2. **Technical publication hygiene:** Run `make release-links`, `make release-preview-plan`, `make release-check`; these are checks, not licensing or safety approval. Do not change `scripts/check_open_source_readiness.py` to report readiness without independent author/rightsholder evidence.
3. **Exact paper coverage:** Compare every feature and experiment statement in the author's *current* Overleaf source against the corresponding implementation, support limitations, original source revision, device/clock/toolchain/seed, SHA and actual results. Do not assume archival GitHub LaTeX is the latest draft.
4. **Scientific novelty:** Compare exact supported semantics with pinned independent Allo and where relevant CODO/ST-Flow. Unsupported competitor constructs and environment setup failure must not be counted as compiler verification failures.
5. **Native and board:** Hardware speed, area or frequency claims require correct matched numerics, native constraints, timing+hold+DRC signoff and measured runtime. Preserve original R3/R4 and native attempt locks; new experiments must be separately preregistered and explicitly executed by the rights holder.
6. **Legal publication:** Obtain Radboud/institutional IP, third-party and collaborator approvals, choose and grant a genuine source license, scan full Git history for secrets/rights, and create a reproducible rights-cleared release artifact. A public repository URL is not an operative research license.

## Bottom line

FPGAI has meaningful implemented **bounded** compiler functionality. The missing requirements for an unqualified publication-ready claim include broader contract/general operator coverage, executed external capability comparisons, strict physical qualification, reproducibility packaging and human-authorized licensing. These are not fixed by merely marking all Python unit tests green.

## 10 November 2026 — substantive bounded NCHW C1 contract extension

**Implementation candidate, not yet evidence:** The canonical NCHW NumPy source-access oracle now derives mapped Conv per-tap owners independently of `resolver.coordinate` (local output-channel tile, replica, PE, per-reduction-tile SIMD lane, serialization fold). A model and its source emitter sharing a wrong owner can no longer be certified simply because the two use the same coordinate helper. The NCHW source trace verifier now checks that each output element's modeled intermediate-source reads occur **before** its commit, in addition to input value readiness, last-reader scratch release and exact read-token multiplicity. All Conv actual GCC taps from supported generated source are passed to the stronger independent oracle. The new tests include common-mode owner corruption and a complete/readiness-safe but causally invalid reordered COMMIT.

**Boundary:** The source contract remains E0 + selected observed GCC E1, for static rank-four supported Conv/Relu/Add/Concat/MaxPool DAGs with a single runtime input/final output and bounded events. Initial external input taps, all scalar READ/COMMIT source timing, hardware PE/ports/clock cycles and automatic memory reuse in the stock HLS emitter are not proven. Unlike original finite C1/C2 experiments, these new tests and exact SHA have not yet been executed by the author; no numerical counts, novel source-case populations or publication claims may be added to the paper based solely on this commit.

**Next higher-priority still-open manuscript gates:** the author's current Overleaf text versus actual supported source domains; true independent pinned Allo comparison including published FIFO and safe reorder controls; exact-source original C1/C2 artifact reproduction/release rights; and timing+DRC/board qualification for physical claims. The Allo research checkout requires its own separate licensed/LLVM environment and explicit execution; it has not been executed here.
