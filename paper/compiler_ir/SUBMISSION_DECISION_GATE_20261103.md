## Publication claims and pass/fail rule

**Claim C1: semantic-preserving, independently mapped operator-local architecture with complete neural-network source integration.** Requires original R2z six-packaged source campaign, twelve actual GCC stage trace executions, all negative-configuration tests and independent SHA rederivation. The standard Conv/Dense functionality is **engineering coverage**, not by itself novelty. For a theory novelty claim, additionally provide preconditions and a separate independent checker/counterexample against closest competing methods.

**Claim C2: original native HLS feasibility for a set of complete mixed CNNs.** The original six Vitis invocations are complete, with 6/6 numerically qualified E2 and 4/6 strict E3 at requested 10 ns / explicit 1 ns uncertainty. Two original strided-CNN arms are source-attested 9.181 ns versus 9.0 ns effective-budget failures; preserve both rejected E3 outcomes. Among the two qualifying matched pairs, independent per-operator Phi increased HLS worst-cycle/resource estimates and did not change HLS BRAM18k. This supports limited feasibility/negative results, **not** a general speedup, bit-exact all-input proof, or qualified physical outcome.

**Claim C3: physical memory/performance benefit.** **Not currently available.** Requires E4 source/RTL/ROM/report SHA, complete placement and routing, timing feasibility and independently verified *clean DRC* for both arms in a matched pair, under the same part/constraints/semantics. A reported but warning-laden DRC has its own descriptive tier and cannot be presented as strict E4. The original 8 unattempted R2y cases must not be converted to assumed outcomes. If no E4 pair qualifies, explicitly say physical translation is unresolved and frame paper as **source/HLS evidence only**, not a hardware advantage.

**Claim C4: distinguishable scientific IR mechanism relative to prior work.** Current public papers from **Allo, StreamTensor, Filament, CODO, hls4ml, SODA, Dahlia and ATLAS** overlap with broad composition, temporal types, neural source codegen and optimization. See [checked prior-art matrix](RELATED_WORK_COMPILER_IR_NOV2026_VERIFIED_MATRIX.md). Require at least one **concrete, independently inspected competing implementation artifact or explicitly reproduced model/tool comparison**, then state only the precise observed capability/theorem gap. No blanket firstness claims.

**Claim C5: reproducibility and reproducible negative results.** State original Git SHAs, tool versions, input/testbench and report digests, all denominators, exact codegen mode and precision, source-only vs original vendor calls, resource estimates vs measured resources, all DRC violations and the full negative/null population. Reference the original source-generated output folders as *local research artifacts*, not downloadable public datasets until a separate artifact publication decision and sanitization.

The paper may be scientifically viable without a positive physical speedup if it provides a clearly novel **source-verified compiler representation or bounded negative translation result** backed by independent comparisons and relevant limitations. It is **not defensible** to assert general FPGA efficiency, arbitrary graph temporal correctness or RL superiority from the current evidence.
