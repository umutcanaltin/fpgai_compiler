# Publication review: concrete compiler IR and CNN accelerator prior art (November 2026)

**Status:** Source-based *public paper/abstract/repository feature inventory*. These references were checked from public primary publication or author/project pages, **not yet independently reproduced under the same models, device, fixed-point tolerances or HLS flags**. The claims here should not be converted into negative claims that a competing system categorically *cannot* express a mechanism. The actual paper remains **MAJOR REVISION**.

The latest R2z coding sprint adds full bounded sequential CNN→Flatten→multi-Dense *engineering coverage*. Existing systems already compile neural networks with convolutional and fully connected layers. The main research question has to be a narrower, falsifiable **typed operator-local architecture plus tensor edge-lifetime/ownership/source-refinement** mechanism, with evidence that this compositional representation prevents concrete invalid mappings and changes actual emitted execution/provenance in ways not already covered by the state of the art.

## Pre-registered questions for evidence, not marketing claims

**Q1. Operator identity and independent Phi:** Can the same complete Functional Model IR preserve its weights, tensors and layer ordering while changing only individual Conv/Gemm `replica/pes/simd/fold/tile` requests? R2z's six E1 generated-source cases and the R3a 3 matched original HLS pairs can test this. The current canonical compiler already has individual operator mapping, so the critical comparison is an **ablation or independent tool baseline**, not mere demonstration that two generated sources are different.

**Q2. Typed intermediate lifetime / last-reader ownership:** On multi-reader MatMul and NCHW graphs, which precise READ/COMMIT ordering and storage-overlap counterexamples does the immutable source E0 contract detect? Compare R2r's 216 bounded generated-source mutants and R2q's explicit **no-gain under hypothetical first-MAC inplace accounting**, while noting that 216/216 mutations are a *selected family* not proof of general RTL correctness. An equivalent invariant in Allo/StreamTensor/Filament may reduce novelty.

**Q3. Source-to-native translation:** Do reduced logical scratch elements yield a corresponding resource estimate or physical decrease? R2v original HLS source factorial was **2 BRAM-estimate decreases, 47 ties, 8 increases, 7 E3 UNKNOWN** among 64; no blanket savings claim. The original R2y first Vivado run exited 0 but was **DRC-warning-only, not E4**; original remaining 8 are not yet routed. R3a will test **different operators and full network structures** at 10 ns/1 ns and strict source-attributed E2/E3 before any physical comparisons.

**Q4. Scientific contribution vs engineering:** CNN+Dense support by itself is **engineering completeness**. A publishable theory contribution needs a clear theorem/precondition/counterexample relative to exact prior definitions, supported by an independent checker or witness; a systems contribution needs matched end-to-end native baselines and realistic networks. A negative source→HLS memory-translation result is legitimate if presented as a bounded, controlled observation with all unknowns—not a fabricated universal improvement.

5. **Manuscript scientific coherence:** revise dated limitations and fix nomenclature E0 formal source, E1 generated GCC, E2 genuine fixed-point Vitis CSim, E3 qualified HLS estimate, E4 qualified routed OOC, never as generic “performance” evidence.
6. **Reproducibility:** independently verify original file counts and write a neutral artifact README with *exact* source commit/CLI/env; do not include temporary credentials or accidentally commit large native build trees; no GitHub Actions and frozen RL changes.
