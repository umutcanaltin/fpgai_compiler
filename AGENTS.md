# Engineering rules — FPGAI Gym Graph RL research

**Canonical scientific contract:** [rl_environment/RESEARCH_QUESTION.md](rl_environment/RESEARCH_QUESTION.md). Read it **before** coding. It supersedes older experiment hypotheses but never changes historic source-bound claims.

## Active research boundaries

1. **One Gymnasium environment, one shared GNN, one shared DRL policy.** Initialize its parameters **from scratch** and train *online in our environment* across distinct network episodes. No pretrained model, offline DRL stage, surrogate HLS reward or policy per network.
2. **Observation:** complete real Functional Model IR graph of variable size (types, dimensions, connections), usable five-resource FPGA capacities, numerical error bound, **internally generated bounded clock-action search domain (never provided by experiment user as an input clock grid)** and dynamic original HLS feedback. **Never provide a predetermined desired clock, assumed achievable maximum frequency, or a fixed default clock as a Gym task input.** Keep GNN node embeddings and pooled global embeddings. Do not call shallow handcrafted mean pooling a trained GNN.
3. **Action:** one complete compiler-legal architecture across all operators **plus a global requested HLS clock period, selected by the policy itself**. Every Gym task is initialized with `clock_ns=None` and the shared learnable Beta clock actor outputs **floating-point period_ns** (0.001 ns canonical Tcl resolution) jointly with the compiler-legal architecture. Only a source-defined safety interval **2–32 ns** bounds its proposals; there is **no clock grid**, no presumed feasible frequency, and no user clock input in the normal study. A specific clock may be imposed only by the explicitly labeled fixed-clock ablation. Precision is model-global until verified per-edge casts exist. Do not edit emitted HLS text directly or silently ignore requested knobs.
4. **Exactly one objective:** **minimize HLS-timing-feasible, numerically/resource-qualified estimated whole-network latency in ns**, computed as original HLS worst-case cycles × requested period. Do **not** reward fewer LUT/FF/DSP/BRAM/URAM, lower power, energy, or Pareto efficiency. All usable resources may be consumed.
5. **Hard constraints:** original CSim numerical error <= target tolerance, original HLS-estimated resource usage within usable limits, **original HLS EstimatedClockPeriod must not exceed (requested TargetClockPeriod − reported ClockUncertainty)**, with original report target, estimate and uncertainty present, unique, source-attested and clock-bound. Missing/conflicting HLS timing => not qualified. Never call requested frequency achieved/physical Fmax. HLS-level timing is not routed evidence.
6. **No Vivado and no board claim.** No physical place/route, routed Fmax, measured latency or energy in this RL environment. Preserve other research history as archived Git commits only.
7. **Vendor security:** original Vitis may execute only on explicit foreground opt-in, within a declared bounded number of calls and timeouts, with immutable per-case staging and clean source-pinned revision. Tests/reset/report/plan/audit must invoke **zero** vendor tools; no native CI.
8. **Provenance:** hash source, model including weights, numerical samples, requested clock, emitted HLS and Tcl/testbench; record Vitis version, original receipt, CSim, numerical/resource/timing qualification and wall-clock cost. Missing is null, never a fabricated zero or proxy measurement.
9. **Training/evaluation:** train the same randomly initialized GNN/policy online across training tasks; save checkpoints produced by this training. Validation/test with frozen policy cannot backpropagate; separate matched online-adaptation treatment only with explicit contamination accounting. Fixed budgets and seeds for all real-HLS baselines.
10. **Scope and legitimacy:** only support network/operator/FPGA types genuinely compiled by the existing academic compiler. Initial code handles small MatMul/Gemm only. Never assert CNN, attention, arbitrary graphs, cross-part generalization, optimality or learned improvement without original matching evidence.
11. **Tests:** independently audit original receipts, keep core compiler tests, add focused negative tests for every new Gym/GNN/clock/timing/reward feature, and rerun targeted/full surviving suites before claiming verification. The legacy `study.py` is dry-run only and retired for native execution; use `gym_study.py` and the separate `gym_audit.py` for new cases. Do not say a tool was run if only a GitHub edit occurred.
